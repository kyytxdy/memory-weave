# 织忆 · Memory Weave

SillyTavern 长期记忆扩展。移动端优先，玻璃拟态界面。

自动把对话织成记忆，再在需要的时候还给你。

---

## 三层记忆

角色扮演聊久了会失忆。原因通常有两种：要么把全部原文塞进上下文，越聊越贵、最后被截断；要么只保留一份笼统的总结，细节全糊在一起。

这个插件用三层解决：

**时间线 —— 每轮一句话（默认 50 字）**

一轮对话结束，压成一句话记进时间线。写清谁做了什么、结果如何，保留人名和具体动作。粒度细，翻回去能找回「她当时到底说了什么」。

**记录 —— 每 10 轮一段概要（默认 200 字）**

攒够 10 轮，把这段时间线摘要合并成一段完整概要。写清整体走向、关系变化、留下的悬念。用的是已有短摘要而不是重读原文，省 token，也更连贯。

**人物档案 —— 一人一卡**

人多起来，光有时间线不够用：你记得"那天在药房吵了一架"，但想不起来吵架的人是谁、什么立场。人物档案按人建档，一个人一张卡，每轮自动更新，覆盖旧值。

新人物出现时由模型判定重要度，达到门槛才建卡。超过设定轮数没再出现，标为「离场」而不是删除——删了就找不回来，标一下还能在剧情里回归，档案原样留着。

三层各有各的位置，注入时全部带上，人物档案排在最前面——当下的关系状态最要紧。

> 两层摘要的思路来自 [Memory Books](https://github.com/dddanny79/SillyTavern-MemoryBooks) 的 Scene / Arc 设计：底层频繁、细粒度，上层低频、捕捉变化，且上层从下层生成而非重读原文。

## 每轮只发一次请求

三层如果用三次独立调用去做，会撞上一个很实际的问题：它们要抢同一把锁。模型一慢（推理模型的 `reasoning_effort` 调高时，一次生成要二三十秒），先起的那个占着锁不放，后面的等不到就被丢弃——人物档案会长期停在 0 人，而界面上看不出任何报错。

所以默认是**合并调用**：一轮对话只发一次请求，模型按固定标签一次产出全部内容。

```
<thought>
谁做了什么、哪些人物出场、有没有人离开。简短自述，不用给人看。
</thought>
<content>
<beat>一句话，50 字左右</beat>
<people>
【人物名】重要度:1-5
身份：药房主人
</people>
<arc>够轮数时才出现的一段概要</arc>
</content>
```

三个好处：

- **锁只有一个占用者**，时序问题从结构上消失。
- **模型在一段上下文里同时看到剧情和人物**，不会出现总结说「两人闹翻」而档案还写着「关系和睦」。
- **每个标签各自解析**，某个标签缺失不影响其它部分；旧版那种「整段回复按行拆成多条记忆」的碎片化不可能再发生。

`<thought>` 里的内容解析时直接丢弃，只作为模型自己的草稿。这是有意留的——与其压制它的推理，不如划一块地方让它想完，正文反而干净。

标签对不上时不会静默失败：把模型上一次的坏输出连同具体问题回灌回去，要它重写一次。比如「你的 `<beat>` 照抄了原文的句子，那不是总结」。只有两次都不达标时才退回本地截取，保证时间线不断链。

设置里可以关掉它，改回各自单独请求——如果你更想分别控制每一步的间隔，或者接的模型对多任务提示词不友好。

## 参数

| 项 | 默认 | 说明 |
|---|---|---|
| 一次请求做完 | 开 | 时间线、人物、大总结用同一次调用；关掉则各自单独请求 |
| 时间线间隔 | 1 轮 | 每几轮记一条短总结 |
| 大总结间隔 | 10 轮 | 每几轮合并一段长概要 |
| 注入条数 | 6 条 | 带多少条短总结进上下文 |
| 人物保留 | 10 轮 | 超过这么多轮没出现就标为离场 |
| 建档门槛 | 重要度 3 | 低于这个分数的新人物不建档，5 最难 |
| 记忆风格 | 档案 | 影响提炼语气：档案 / 日记 / 关系簿 |

大总结固定带最近 2 条，不单独暴露。

| 注入全部条目 | 关 | 不再只带最近几条，所有摘要都进上下文 |
| 旧对话移出上下文 | 关 | 已总结的部分用 `/hide` 隐藏 |
| 始终保留最近 | 20 轮 | 最后这么多轮原文不动 |

**注入条数别调太高。** 一条短总结约 50 字，六条约 200–300 token。设到 20 会明显挤压角色卡和世界书的预算。

## 上下文预算

聊到几百轮之后，真正的瓶颈不是记忆不够，是原文把上下文塞满了。

两个开关配合使用，把「原文」换成「摘要」：

**注入全部条目** —— 关掉条数上限，所有时间线和大总结都进上下文。条目多起来 token 会涨，但因为每条只有一句话，总量远小于原文。

**旧对话移出上下文** —— 已经总结过的部分，用 `/hide` 从提示里摘掉。界面上还能看到、还能翻，只是模型读不到了。

这两件事必须一起做，顺序也不能反：

```
先总结 → 确认摘要生成成功 → 才允许隐藏
```

代码里的上界取的是 `min(摘要覆盖到的轮次, 总轮数 - 保留轮数)`。没总结到的部分永远不碰——隐藏了没总结的对话，等于把信息直接扔掉。

**始终保留最近 N 轮** 是安全垫。最后 20 轮原文不动，模型有足够的上下文接住当前话题，摘要只负责更早的部分。

隐藏是可逆的。设置里有「把隐藏的消息放回来」，调用 `/unhide` 还原。

**这会影响别的扩展。** 向量检索、Chat Vectorization 之类的功能依赖原文消息，消息被隐藏后它们就检索不到了。如果你在用这类插件，这个开关建议关着。

## 提示词

合并调用下只有一段提示词，按标签分段。全文见 `index.js` 的 `buildRoundPrompt()`，是纯字符串数组，改起来不用碰逻辑。

三条约束是有意写得这么硬的：

**「这是一次文本处理任务，不是角色扮演」放第一行。** 不写这句，模型会以为你在让它继续写故事——早期版本返回的就是续写而不是总结。

**「用名字指代，不要用他/她/对方」。** 这是全篇最要紧的一条。不写它，三天后的记忆里全是「他说」「她笑了」，等于没记。

**每个字段带一句 hint。** 比如「年龄」的提示是「对话里明确提到才写，不要推测」。这比在别处泛泛写一句「不要编造」管用：限定写在字段旁边，模型才会照着做。hint 在模板编辑器里可以逐条改。

```
—— beat
- 写清谁做了什么、结果如何，保留人名和具体动作。
- 用名字指代，不要用「他」「她」「对方」。
- 不复述台词，不评价，不写「接着」「这一轮」「然后」这类过场词。
- 50 字左右，最多 70 字，只写一句话。

—— people
本轮出场的人物，每人一段，以【姓名】重要度:N 开头。
所有人共有的字段：身份（职业或社会角色，一句话说清）、年龄（对话里明确提到才写，不要推测）、最近动态（这一轮里这个人做了什么）
除「林染」以外的人物，另外填：关系（和玩家角色的关系）、对我的态度（从语气和举动判断，不要猜内心）
如果这个人就是「林染」（玩家自己），改填这些：时间（故事内的第几天、什么时辰）

—— arc（够轮数时才出现）
- 把下面这些短摘要合并成一段连贯概要，200 字左右，最多 260 字。
- 写清整体发生了什么、人物关系有什么变化、留下了什么悬念。
```

### 资料来源：对话 + 背景设定

只给模型「本轮对话」是不够的。年龄、生日、常驻地在对话里往往从来不说——它们写在角色卡里。

所以每次调用都带两份材料：

```
<背景设定>
角色名：露西艾拉
设定：精灵族药师，银发长耳，219 岁，生日在初雪那天，常驻城南药房。

我（玩家）：林染，少年，约十五岁。
</背景设定>

已有档案（只补本轮的变化，不要重复描述）：
- 林染（我）：少年
- 艾拉：精灵，照顾林染的人

本轮对话：
林染：别走。
露西艾拉：……手松开。
```

提示词里明写：**背景设定里明确写了的，直接取用，不要因为本轮对话没提到就留空。** 这句话是关键——不写它，模型会严格按「只说发生过的事」理解，把角色卡里明明有的年龄生日全部跳过。

**已有档案**那一小段是为了让模型知道谁已经在册，避免同一个角色换个称呼又建一张卡，也让它知道哪些字段还空着、该补。

代价是每次多几百 token。嫌贵可以在代码里把 `backgroundBlock()` 的截断长度调小。

### 空字段会显示成「—」

人物卡里，没有值的字段不隐藏，用压暗的「—」占位。这样一眼能看出缺什么，点「修改」直接补。

不隐藏是有意的：把空字段藏掉，你会以为表填全了。

### 输出怎么处理

模型返回后按四步走：

1. **剥思维链** —— 推理模型（DeepSeek V4、R1 一类）会把 reasoning 一起返回，按结束标记切掉；只有开始标记说明整段都是思考，判废。
2. **取标签** —— `<beat>`、`<people>`、`<arc>` 各自独立提取，`<thought>` 整段丢弃。某个标签缺失不影响其它部分。
3. **判废** —— 「我无法」「抱歉」开头、长度不足、或者大段文字能在原文里找到（复述而非压缩），都算不达标。
4. **回灌重试** —— 把坏输出连同具体问题发回去再要一次，仍然不行才退回本地截取。

**第 3 步的复述检测值得单说。** 早期版本存进去的记忆里有一整段「这是你需求的最终输出：……」，因为模型把它当成了续写任务。现在取总结的三段特征串去原文里比对，命中两段就判定为复述，重新问一次。

## 人物模板

模板只有一个：人物档案。一个人一张卡，同名自动合并。

| 字段 | 位置 | 谁有 |
|---|---|---|
| 姓名 | 标题 | 所有人（卡片的 key） |
| 身份 | 主体 | 所有人 |
| 年龄 | 主体 | 所有人 |
| 最近动态 | 主体 | 所有人 |
| 关系 | 主体 | 只有 NPC |
| 对我的态度 | 主体 | 只有 NPC |
| 时间 | 主体 | 只有主角 |
| 所在地 | 折叠 | 所有人 |
| 生日 | 折叠 | 所有人 |
| 外貌 | 折叠 | 所有人 |
| 备注 | 折叠 | 所有人 |

### 为什么主角和 NPC 不一样

因为你和别人的关系不是对称的。

看别人，你关心的是「他是谁、他跟我什么关系、他现在怎么看我」。看自己，这三条全是废话——你当然知道自己是谁。你需要的是「我打算干什么、我现在什么处境、身上带着什么」。

所以主角卡不显示「关系」和「对我的态度」，换成「时间」——故事进行到第几天、什么时辰。界面上主角卡是金边、带「我」标记、永远排第一个。

模板里用 `scope` 标记字段归属：

```json
{ "id": "goal", "label": "当前打算", "type": "text", "group": "main", "scope": "self" }
```

`self` 只在主角卡出现，`npc` 只在其他人物卡出现，不写就是通用。

主角是谁由 `ctx.name1`（你的人设名）判定，所以人设改名后旧卡不会自动跟着变——需要的话手动改一下。

### 人物是怎么建的

每轮对话结束，把最近一轮和字段清单发给模型：

```
【艾拉】重要度:5
身份：药房主人
年龄：二十七八
关系：收留我的人
对我的态度：表面冷淡，实际处处照应
最近动态：端着温水上楼，提起周老板问过林染的来历
```

重要度分五档：

| 分数 | 含义 |
|---|---|
| 5 | 主角或贯穿剧情的核心角色 |
| 4 | 有名字、有独立台词、之后大概率还会出现 |
| 3 | 有名字、有明确互动 |
| 2 | 只被顺口提到一次 |
| 1 | 背景路人 |

低于门槛（默认 3）的不建卡，路人不占位置。

**同名合并，不重复建。** 字段增量覆盖：模型这轮没提到的字段保留旧值。一次漏读不该抹掉已知信息。

**超过 10 轮没出现就标为「离场」**，轮数在设置里调。判的是「最后一次出现到现在的轮数」，不是按时间或字数。

离场不删除，只是压暗、名字加删除线、排到列表底部。理由很实际：删了就找不回来。角色过二十轮又回来了，档案立刻恢复原样——`upsertEntity` 见到同名会清掉离场标记。主角永远不标离场，那条判定按人设名走。

真要彻底删掉，展开卡片点「移除」，那是手动的、不可撤销的删除。

### 为什么不让它写「动机」

有一条线：**只收对话里能直接观察到的东西。**

身份、年龄、外貌、说话方式，是别人看得见听得见的。动机、隐藏立场、真实情绪不是——让模型填这些，它一定会编。编出来的内容写进档案，下一轮被当作设定注入，角色就开始按编造的人设演，越走越偏。

每个字段还能写一句提示词（`hint`），会拼进给模型的字段清单里。比如「年龄」的提示是「对话里明确提到才写，不要推测」——这比在模板说明里泛泛写一句「不要编造」管用得多。

### 改成你自己的

`templates/person-card.json` 是模板的可编辑版本，改完从「模板 → 导入 JSON」导入。也可以在界面里点「＋ 新建模板」。

字段类型：

```json
{ "id": "mood", "label": "气氛", "type": "select", "group": "extra", "options": ["平静", "紧张"] }
```

- `text` 单行
- `textarea` 多行
- `select` 选项（需要 `options`）
- `tags` 标签（回车添加）

## 几个说明

**升级后旧记忆不会自动迁移。** 上一版的条目是碎片化的原文摘录，没法自动修复成一句话总结，硬转只会把噪音带过来。新版从当前楼层往后开始记，旧数据仍留在 `settings.json` 里不显示，设置页点「清空」会一并清掉。

**不想每轮都调模型** 就把「时间线自动记录」关掉，改成想记的时候点「记一条」。手动触发需要至少有一轮新对话。

**大总结依赖时间线。** 如果时间线关掉了，大总结没有素材可合并，会自动跳过。想补历史先点「补全部」，它会按间隔一路补到当前位置。

**换模型可能失败。** 提炼走 `generateRaw`，不行退 `generateQuietPrompt`（两种签名），再不行退截取原文。都不会污染聊天上下文。

**数据存在 `extensionSettings['memory-weave']`**，跟着 `settings.json` 走，按 `角色头像::聊天文件名` 隔离。删扩展目录不会丢数据。

## 排错

设了这么多层解析，出问题时猜是没用的——得看模型到底回了什么。

**面板 → 设置 → 排错 → 最近一次调用**，打开后是这个样子：

| 项 | 含义 |
|---|---|
| 用的模板 | 本轮人物写进了哪张模板 |
| 解析出人物 | 从 `<people>` 里认出几个人 |
| 落库 | 真正写进档案几个 |
| 低于门槛丢弃 | 因为重要度不够被挡掉的 |
| 字段命中 | 哪些字段真的匹配上了 |
| beat | 生成的那句总结 |

下面附本轮对话节选和**模型原始输出**全文。判断很快：

- 解析出人物 0、原始输出里也没有 `【名字】` → 模型的锅，改提示词或换模型
- 原始输出里有 `【名字】` 但解析出 0 → 解析的锅，把原始输出贴给我
- 解析出 2 个、落库 0 个 → 门槛设太高，调「建档门槛」
- 字段命中只有一两个 → 模型没写全，看提示词里的字段清单

同样内容也会打到控制台（`[织忆] 本轮 · 解析 N 人 · 落库 N 人 · 字段 …`），后面紧跟原始输出全文。

## 控制台

```js
MemoryWeave.open()        // 打开面板
MemoryWeave.weave()       // 立刻总结一条
MemoryWeave.backfill()    // 补齐全部历史
MemoryWeave.fill()        // 立刻重填快照
MemoryWeave.form()        // 手动填表
MemoryWeave.debug()       // 打开排错面板
MemoryWeave.info()        // 当前聊天记了多少
MemoryWeave.last          // { raw, info } 最近一次的原始输出与解析结果
```

`MemoryWeave.info()` 会列出每条快照的模板名、更新时间、已填字段数，排查问题时先看它。
